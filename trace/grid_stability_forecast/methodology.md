# Grid-stability forecast methodology

The supplied research design is the governing methodology. This implementation measures the sum of eight GPU power channels from the high-resolution node dataset. It does not measure PCC active power, frequency, voltage, CPU, cooling, or facility power. All ramp results are therefore GPU-load proxy metrics.

The control boundary is `P_grid = P_main_controlled + P_other + P_filler + P_charge - P_discharge`. Only a hypothetical filler is simulated here. The reference is a ramp-limited trajectory; a delayed, capacity-limited command attempts to fill downward residuals. Its assumed 200 W/s ramp limit, 500 W capacity, and 200 ms delay are scenario settings, not device measurements or grid limits. Cap, DVFS, battery, scheduling, and firmware smoothing remain requirements, with no causal effect claimed.

Targets are issued after a valid 200 ms bin completes. The +1 s power target is the completed bin with right edge one second after issue. Endpoint delta is that target minus current power. A future-path event is any intermediate completed bin crossing the scenario 100 W rise/drop threshold. Maximum upward and downward ramp use consecutive 200 ms future bins. Segment boundaries and timestamp gaps invalidate the whole history plus horizon window. Metadata comes from run-level source metadata and filename tokens available before issuance. A later audit found timestamped NLR online-rate vLLM running/waiting-request and throughput counters about every 10 s. These are used only after a conservative 1 s availability lag in a separate within-acquisition pilot. Per-request arrival and training phase traces remain unavailable; server/power clock synchronization is unverified.

The new experiments use 22 grouped train runs and 10 grouped test runs, one fixed historical LightGBM setting, one seed, 15 quantiles, and 200-2000 ms horizons. Conditions are history-only, coarse static S1, and expanded static S2. The +1 s cell has five training-run metadata permutation controls, future-path event-window classifiers, an independent-run learning curve, and idealized filler replay. Eight leave-one-static-feature-out fits were later run for the +1 s cell with the same split, rows, weights, and fixed model capacity. The +1 s staged grouped inner search with controlled/independently tuned S2 and three sampling seeds is complete on the reused outer holdout. Retrospective unseen GPU/workload combination evaluation with three seeds is also complete. The outer-5/inner-3 staged search completed. A separate one-to-one matching evaluation maps the existing event-window probabilities to 200 ms step onsets, with missed events and false alarms recorded; its onset definition differs from the classifier training label. Independent new-session validation remains outstanding. The existing 1/2 s evaluations are historical comparisons and are not substituted for new results. The quantile CRPS approximation is twice the trapezoidal integral of pinball loss over the actual quantile grid, with endpoint quantiles held through the tails. Each score is averaged within run, then equally across runs. CI resamples paired test runs from stored predictions; it excludes fitting and model-selection uncertainty.

The center-aligned median smoothing in `preprocessing/powerprep/events.py` uses future samples and its recovery 10-90% search begins at low entry. Its reported event count is not adopted as a verified physical event count. This pilot labels threshold crossings directly from future trajectories and does not claim recovery-time accuracy.

Supporting technical sources provided with the task: [Choukse et al.](https://arxiv.org/html/2508.14318v2), [NVIDIA SMI documentation](https://docs.nvidia.com/deploy/nvidia-smi/index.html), [NLR submission 312](https://data.nlr.gov/submissions/312), and [Elsayed et al.](https://www.nature.com/articles/s41597-026-07496-6). Their descriptions of techniques and datasets are distinct from this project's reference controller and scenario values.

The historical NLR training long-valley/fast-recovery count was remeasured on identical v2 200 ms bins. The legacy 10–90% routine found 14 events in 11 runs; the final-recovery-episode routine found 96 in 31 runs with identical 5,034 detected event identities. This changes the interpretation of the old exploratory count; see results/event_v2_nlr_training_20260926/report_ko.md. Both are offline labels using centered smoothing.

The source-timestamp audit found 32 nonoverlapping highres traces across four dates, with each date perfectly confounded with one GPU×workload cohort. Run-level bootstrap intervals cannot establish independent-day generalization. A separate fixed-setting 5/10/30 s pilot and an NLR online-rate B1–B4 within-acquisition runtime-log pilot are reported in their own result directories.

The NLR training +1 s model/node pilot is a separate 41-job CPU+GPU experiment. It uses one grouped job per model×node-count condition as test, without mixing scores with the highres eight-GPU experiment. Its source project may contain dependent repeats, so its eight-job effect is descriptive.
